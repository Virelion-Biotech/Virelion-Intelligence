# Virelion module mapping

Mappings are configuration-backed. A finding may map to one or more modules. Mapping is an analytical recommendation, not evidence that a module already implements the capability.

| Module | Typical signals |
|---|---|
| CardiAtlas | cardiac omics, disease atlases, MI datasets |
| CardiBench | datasets, benchmarks, ML comparisons |
| CardiEval | evaluation, reproducibility, model validation |
| ElectroTrace | ECG and electrophysiology signals |
| MyoTrace | cardiomyocyte maturation and phenotype tracking |
| OptiCell | iPSC/cell quality and maturation |
| CardiLearn | cardiac ML and representation learning |
| CardiSim | simulation, mechanistic or engineering models |
| CardiTrace | longitudinal cardiac phenotyping |
| CardiBridge | multimodal data integration |
| HeartTwin | multimodal cardiac modeling and digital-twin concepts |

Every mapping should include the matched domains and a rationale. The underlying paper/dataset evidence remains authoritative; the mapping is Virelion analysis.
